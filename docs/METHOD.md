# Delivery method — candidate

Specification-first without waterfall: define the outcome and acceptance test for a thin vertical, implement, run, measure, review independently, then update specs with findings. Combine DDD, lightweight hexagonal boundaries, evidence-driven and test-driven development, event-driven projection and Lean/IBRL. Use a single active implementation vertical unless a parallel experiment clearly helps and does not block it. Treat this project as a self-observation pilot.

G0 foundations: S00/S01/S02/UC-001, architecture candidate. G1 single PR projection + initial objective/gap demonstration. G2 durable live webhook ingestion and reconciliation. G3 backfill and coverage; experiments may run in parallel. G4 multi-scale observation and metrics. G5 semantic assessment with abstention and independent evaluation. G6 consumer projections; career evidence may be delivered earlier as a private thin slice.

Per cycle: hypothesis, acceptance criteria, minimal implementation, test result, actual run receipt, measured cost/benefit, known gaps and next decision. Reuse source authorities, avoid duplicating data. Merge/deploy/run/publication remain distinct decisions. Do not force a TID for every local lesson; candidate cross-project lessons require evidence and owner review.

Metrics: acquisition coverage (known/unknown denominator), p50/p95 event-to-view delay, throughput, bytes/API requests, replay divergences, factual precision and abstentions, assessment agreement, actual decisions helped, time human/agent and resource cost where measurable. Set thresholds after baseline; no global score. Compare changes on matched scope, not raw activity counts.
