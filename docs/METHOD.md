# Delivery method — candidate

Specification-first without waterfall: define the outcome and acceptance test for a thin vertical, implement, run, measure, review independently, then update specs with findings. Combine DDD, lightweight hexagonal boundaries, evidence-driven and test-driven development, event-driven projection and Lean/IBRL. Use a single active implementation vertical unless a parallel experiment clearly helps and does not block it. Treat this project as a self-observation pilot.

G0 foundations: S00/S01/S02/UC-001, architecture candidate. G1 KPI-001: first evidence-backed CV revision; single PR projection is a technical probe, not a gate to unnecessary infrastructure. G2 durable live webhook ingestion and reconciliation. G3 backfill and coverage; experiments may run in parallel. G4 multi-scale observation and metrics. G5 semantic assessment with abstention and independent evaluation. G6 generalized consumer projections; career evidence is delivered first in G1.

Per cycle: hypothesis, acceptance criteria, minimal implementation, test result, actual run receipt, measured cost/benefit, known gaps and next decision. Reuse source authorities, avoid duplicating data. Merge/deploy/run/publication remain distinct decisions. Do not force a TID for every local lesson; candidate cross-project lessons require evidence and owner review.

Metrics: acquisition coverage (known/unknown denominator), p50/p95 event-to-view delay, throughput, bytes/API requests, replay divergences, factual precision and abstentions, assessment agreement, actual decisions helped, time human/agent and resource cost where measurable. Set thresholds after baseline; no global score. Compare changes on matched scope, not raw activity counts.

## Quality / speed decision rule
Optimize time to first factual CV improvement, not lines of code or specifications. Non-negotiable: provenance, truthful attribution, privacy, explicit uncertainty and reproducible checks for implemented logic. Reuse existing connectors, selective Git/REST queries and manual review when faster. Prefer a bounded corpus and a human-readable claim ledger over a complete data platform. Defer any component not needed to change or verify a claim; record a short reason and revisit only on evidence of need. No additional G0 documents required for G1. Measure KPI-001 elapsed time, meaningful accepted changes, provenance coverage of changed claims and human review minutes; distinguish manual baseline from automated performance. Stop the slice when a materially improved CV is accepted, not when all data is collected.
